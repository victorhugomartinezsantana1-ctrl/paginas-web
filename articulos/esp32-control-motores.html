Control de Motores y Telemetría con ESP32

C++ para electrónica: RTOS, modulación PWM y drivers de potencia en arquitecturas modulares.

por Victor Martinez 2026-10-22 ⏱ 18 min de lectura

1. El Microcontrolador ESP32: Arquitectura Dual-Core

A diferencia del clásico Arduino Uno de 8-bits, el ESP32 es un procesador de 32-bits con dos núcleos y WiFi/Bluetooth integrado. Su programación profesional en C++ implica abandonar el paradigma del "súper loop" (un solo void loop() gigante con bloqueos de tipo delay()) a favor del sistema operativo en tiempo real FreeRTOS integrado.

2. Modulación por Ancho de Pulsos (PWM) en Hardware

Para controlar la velocidad de un motor de un motocarro, no se regula el voltaje analógico; se emiten pulsos digitales de 3.3V a alta frecuencia, variando el ciclo de trabajo (Duty Cycle). El ESP32 tiene un periférico dedicado llamado LEDC.

cpp 
// Configuración del periférico LEDC (Arduino-ESP32 core 3.x)
const int motorPin = 18;
const int pwmFreq = 5000;     // 5 kHz
const int pwmResolution = 8;  // Resolución de 8 bits (0-255)

void setup() {
  ledcAttach(motorPin, pwmFreq, pwmResolution);
}

void loop() {
  // Aceleración suave
  for (int duty = 0; duty <= 255; duty++) {
    ledcWrite(motorPin, duty);
    vTaskDelay(pdMS_TO_TICKS(10));  // cede la CPU a otras tareas, a diferencia de delay()
  }
}

En el core 2.x de Arduino-ESP32 la API era distinta: ledcSetup(canal, frecuencia, resolución) y ledcAttachPin(pin, canal). Ambas funciones se eliminaron en el core 3.x, donde ledcAttach() y ledcWrite() trabajan directamente con el número de pin.

3. Puentes H y Aislamiento

Cada pin del ESP32 soporta como máximo absoluto unos 40 mA (y se recomienda no pasar de ~20 mA). Si conectas un motor de tracción directo, quemarás el chip al instante. Necesitas un Controlador de Motor (Puente H) de alta potencia como un controlador MOSFET. Las señales PWM del ESP32 van a las entradas lógicas del controlador, el cual gestiona los amperios que van desde la batería de alta capacidad hacia el motor.

4. Telemetría Multihilo

Arquitectura RTOS: Asigna el control PWM al Núcleo 1 (prioridad alta) y crea una Tarea (Task) de FreeRTOS en el Núcleo 0 (prioridad baja) para leer sensores de corriente y enviar datos vía WiFi (WebSockets) o Serial a una interfaz, evitando que el procesamiento de la telemetría retrase el control del motor.

Así se crea una tarea fijada al núcleo 0 con xTaskCreatePinnedToCore:

cpp 
void tareaTelemetria(void *parametros) {
  for (;;) {
    // Leer el sensor de corriente y enviar el dato por WiFi o Serial
    vTaskDelay(pdMS_TO_TICKS(100));
  }
}

void setup() {
  // ... configuración del PWM ...
  // Tarea en el núcleo 0, prioridad 1, pila de 4096 bytes
  xTaskCreatePinnedToCore(tareaTelemetria, "telemetria", 4096, NULL, 1, NULL, 0);
}
