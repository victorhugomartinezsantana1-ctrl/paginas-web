Investigación Profunda: Docker Multi-stage y Distroless

El arte de compilar contenedores inmutables, ultra seguros y de bajo peso eliminando binarios innecesarios.

por Victor Martinez 2026-09-24 ⏱ 12 min de lectura

1. Entendiendo las Capas (Layers) y el Bloat

Cada instrucción RUN, COPY, y ADD en un Dockerfile crea una capa inmutable de solo lectura. Si en una capa descargas 500MB de librerías para compilar, y en la siguiente capa las eliminas (RUN rm -rf /lib), la imagen final seguirá pesando 500MB más porque la capa original sigue existiendo en el historial del contenedor. El Multi-stage resuelve esto cortando la herencia de capas.

2. Patrón Builder-Run: Aplicación Node.js (React/Vue/Angular)

Un escenario clásico del desarrollo Frontend es compilar un código TypeScript/React a JavaScript puro. No necesitas Node.js en producción, solo un servidor web que devuelva estáticos.

dockerfile 
# ETAPA 1: Construcción (Pesa ~1 GB por dependencias en node_modules)
FROM node:24-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci          # Instalación limpia
COPY . .
RUN npm run build   # Compila a la carpeta /app/dist

# ETAPA 2: Servidor de Producción (Pesa ~50 MB en total)
FROM nginx:alpine
# Config personalizada (opcional): reemplaza el server por defecto, útil para el fallback de una SPA
COPY nginx.conf /etc/nginx/conf.d/default.conf
# Copiamos EXCLUSIVAMENTE los estáticos generados por el builder
COPY --from=builder /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

3. Imágenes 'Scratch' y 'Distroless' para máxima Seguridad

Para lenguajes que compilan a binarios estáticos (Go, Rust, C++), no necesitas NINGÚN sistema operativo debajo de tu aplicación. Ni Alpine, ni Ubuntu. Nada. Solo el Kernel de Linux del Host.

FROM scratch: Es una imagen especial vacía (0 bytes). Si compilas tu binario Go de manera estática (deshabilitando CGO), puedes montarlo aquí. Elimina una vía clásica de ataque (la inyección de comandos en una shell) simplemente porque no tiene shell (bash, sh, ash) ni utilidades (ls, curl, wget) instalados. Un atacante dispone de muchas menos herramientas para moverse dentro del contenedor.
dockerfile 
# Compilación para Go asegurando binario estático independiente
FROM golang:1.27 AS builder
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -ldflags="-w -s" -o mi_app

# Producción: Imagen Cero Bytes
FROM scratch
# Los certificados SSL base se deben copiar si la app hace peticiones HTTPS
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
COPY --from=builder /src/mi_app /mi_app
ENTRYPOINT ["/mi_app"]

Si tu aplicación necesita certificados de CA, datos de zona horaria y un usuario sin privilegios, pero no una shell, distroless es el punto intermedio: imágenes mínimas mantenidas por Google, sin gestor de paquetes ni shell.

dockerfile 
# Producción: Distroless estática, ejecutándose como usuario no-root
FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=builder /src/mi_app /mi_app
ENTRYPOINT ["/mi_app"]

4. Ventajas Colaterales

  • Tiempos de despliegue (Pull): Descargar una imagen de 10MB toma milisegundos en el cluster de Kubernetes, permitiendo un escalado automático casi instantáneo (HPA).
  • Reducción de Superficie de Ataque: Sin gestores de paquetes (apt, apk), ni shell, ni dependencias de desarrollo, las herramientas de escaneo de vulnerabilidades (como Trivy o Grype) reportarán muchas menos vulnerabilidades.
